Raw input

—

Straight from the keyboard and mouse, before the mapping. Useful for telling “the bridge is not receiving” apart from “the mapping is wrong”.

Mouse to right stick

Changes apply immediately so you can feel them. They are kept only until a reboot unless you save a profile.

How long the stick takes to follow a change in mouse speed, and to return to centre after you stop. Lower is more direct and more jittery; the tuned default is 80 ms.
Games ignore stick movement below an inner deadzone, so small mouse movements get thrown away. This lifts any non-zero deflection to at least this much and compresses the rest of the range into what is left. Applied to the length of the vector, not per axis, so diagonals do not overshoot. Start at 0 and raise it until slow aiming responds.
Several games apply their own curve to stick input and will not let you turn it off: small deflections get damped so a thumbstick feels controllable. A mouse does not need that, and the damping fights precise aiming. Set this below 1.00 to pre-compensate — if the game squares its input, 0.50 here makes the pair linear again. 1.00 is off.
It cannot undo acceleration that builds up over time, the kind where holding a direction makes the turn rate ramp. That depends on history, not on the current value.

Left stick floor while aiming

Holds the left stick at this much whenever the right stick is deflected, and lets go as soon as the mouse stops. It is a floor, not an addition: real WASD input above it passes through untouched, and input below it is scaled up along the direction you are already pushing.
Only used when the left stick is centred — a magnitude with no direction is not a vector.

What this is, plainly. Every other setting here translates input you actually made. This one fabricates stick deflection you did not make, and the reason to want it is that some games treat “the player is moving” as a precondition for aim assistance. In multiplayer titles that is the kind of input modification that terms of service and anti-cheat address. It is off at 0, which is the default.

Key and button mapping

Tap the key name in the Input column — it turns into press a key now… — then press that key on the keyboard attached to the bridge, not the one you are holding this phone with. Tap it again to cancel.

Mouse buttons and modifiers are chosen from a list instead: a single HID report cannot tell left Ctrl from right Ctrl reliably enough to capture it this way.

InputDoes

Profiles

Save writes the settings in force right now, name included, into that slot and makes it the one loaded at startup. Default puts the built-in factory settings into that slot and keeps them there — unlike resetting the live settings, this survives a reboot. Which profile is active does not change, so resetting one you are not using cannot move you onto it.

Export and import

A profile is plain JSON: readable, editable, and safe to paste between boards. Anything out of range is clamped when it is applied rather than rejected.

Join a Wi-Fi network

With a network stored, the bridge joins it the next time Wi-Fi comes up and stops serving its own access point — so the panel sits at a stable address on your network. If it ever cannot get there, Ctrl+Alt+P on the keyboard forces the access point back.

Firmware

—

The second one relays the image to the input chip over the wire between the boards, because that chip has no network of its own — its USB port is the host side. Takes a few seconds. It verifies the image before switching, and confirms only after staying up for 30 s, so a bad one rolls back there too.

Upload hid_gamepad_bridge.bin for the pad chip. The image is written to the spare slot and verified before anything reboots, and it is only confirmed after the new firmware has stayed up for half a minute — so one that crashes or boot-loops is rolled back on its own, with nothing to press.
